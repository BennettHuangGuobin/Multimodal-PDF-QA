## Planned

近期保留第一阶段审查中的后续项，本轮没有实现：

- **R5：渲染来源溯源。** 区分每页实际生成版本与本次运行环境，避免全部跳过仍覆盖 manifest.renderer.version。
- **R6：依赖可复现性。** 选择已测试版本约束，在干净环境与 Ubuntu CPU 上重跑基础测试；目前没有锁文件或 Ubuntu 实测结论。
- **R7：Adapter 数据闭环。** 结果反序列化、bbox/置信度/区域 ID/关系引用校验、合并与持久化 runner。现有 audit 不代替模型结果质检。
- 特殊 PDF：非默认 UserUnit、CropBox 越界等当前明确不支持，需要独立验证后再扩展；旧受影响页应显式重跑 prepare，未请求历史页不会自动迁移。

模型与后续业务路线仍为 Planned：

1. 在 PolyU GPU 环境独立验证 MiniCPM-OCR；不把深度学习框架加入 Mac 核心依赖。记录版本、图像缩放策略、耗时和显存，输出真实文字与来源；是否能给出可靠 bbox 以实际接口为准。
2. 验证 PP-DocLayoutV3 区域检测及阅读顺序。将输出反变换至统一图像像素空间，建立真实报告少量页的人工校验样本。
3. 实现 Adapter runner、结果校验与持久化，加入区域 ID、置信度、来源、布局类型、阶段恢复策略。没有可靠依据的关系维持空值。
4. 核心 MLLM 提取时尚属性与图文线索，保留 `document_id + pdf_page + region_id` 证据标识；印刷页码作为独立展示字段。
5. 设计受控 Tool Calling 契约，接入经授权的外部数据库，保存查询条件、返回实体与页面/区域证据；随后再考虑完整检索增强系统。

Mac M4 持续承担工程开发、测试及产物检查；RTX 3080 负责未来需要 GPU 的模型推理实验。以上步骤不表示必须依赖该单卡，模型规模适配需实测。第二轮不进行 SSH、模型下载、模型接入或 push；技术审阅采用 Private GitHub，不再生成源码 ZIP。
